# ✨ Features

## Git files generation

Since development usually implies to ignore some files of the project in source control, or to process them specifically, **`nmk-base`** handles generation for git projects files:

- `.gitignore` is generated by {ref}`git.ignore<git.ignore>` task
- `.gitattributes` is generated by {ref}`git.attributes<git.attributes>` task

Both tasks behavior are configured by items described in {ref}`this chapter<git-config>`

## Version detection

Current project version is automatically detected from git tags, and generated in the {ref}`${gitVersion}<gitVersion>` config item.

## Local/CI build context

Current build context is detected from the current environment (i.e. if the **`CI`** env var is set), and following configuration items are generated accordingly:

- {ref}`${isLocalBuild}<isLocalBuild>` is set to `true` if the project is built locally (on the developper PC)
- {ref}`${isCIBuild}<isCIBuild>` is set to `true` if the project is built in CI (on a CI runner/node)

## System dependencies check

The {ref}`sys.deps<sys.deps>` task checks the project system-level dependencies (i.e. those which can't be installed automatically as part of the build environment backend), and displays install instruction if they're missing.

Checked dependencies are configured through the {ref}`${systemDeps}<systemDeps>` item.

## nmk project helper tasks

Some tasks are provided to get information or help on the installed **`nmk`** plugins:

- {ref}`tasks<tasks-task>`: lists available tasks for the current project
- {ref}`version<version>`: displays used **`nmk`** plugins versions
- {ref}`help<help>`: lists available documentation links for used **`nmk`** plugins

## Project clean

Some tasks are provided to clean project files:

- triggered by the global {ref}`clean<clean>` task
  - {ref}`clean.out<clean.out>`: cleans build {ref}`${outputDir}<outputDir>` folder
  - {ref}`clean.lockfile<clean.lockfile>`: cleans declared lockfiles
- to be triggered only on demand:
  - {ref}`git.clean<git.clean>`: calls git command to remove all git ignored files, restoring the project in the same state than if was just cloned

## Python venv handling

Since **`nmk`** project are using a Python venv (local to the project, or a temporary one, depending on the used buildenv backend), following tasks are provided to handle it:

- {ref}`py.req<py.req>`: generates `requirements.txt` file (only if buildenv backend use requirements, see {ref}`${backendUseRequirements}<backendUseRequirements>` item)
- {ref}`py.venv<py.venv>`: triggers venv synchronization, when python dependencies list has been updated

## Lock files

By convention, **`nmk`** projects ignore lock files in source control.

Its goes a bit against reproducible build principle (which is the fundamental purpose of this kind of files), but the preferred behavior is to always grab latest versions when building the project from scratch (in particular in CI environnement). This greatly helps projects to always be kept up to date.

This behavior can be disabled by configuring the {ref}`${backendIgnoreLockfile}<backendIgnoreLockfile>` item to `false`.

## Dirty check

By convention, some files generated by **`nmk`** plugins are expected to be kept in source control.

The idea behind this is that anyone should be able to develop on the project, without triggering the **`nmk`** build if he's not comfortable with the proposed build workflow, by simply using the standard tools the **`nmk`** plugins are based on.

On the other side, it is important for the project consistency to make sure that generated files are always up to date with the latest tools versions. That's why, in CI build context only, the {ref}`git.dirty<git.dirty>` task checks (at the end of any **`nmk`** build) that there is no modified files (compared to the git index).

## Java runtime detection

Some Java-based tools are expecting to find the Java runtime. Provided {ref}`${javaRuntime}<javaRuntime>` item allows them to find it easily.

## Common builders

Some common **`nmk`** tasks builders are provided in the {py:mod}`nmk_base.common` python module, ready to use by other plugins.
